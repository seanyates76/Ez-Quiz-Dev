Reliability-Informed UX Flow

Internal planning brief for aligning EZ Quiz first-use UX with the generation architecture it likely needs next: creation can take time, status should explain what is happening, and Start should only begin a ready quiz.

Created May 15, 2026 Product spine: Create / Status / Start No full async backend yet

New Product Spine

Create builds. Status explains progress. Start unlocks only when ready.

The first-use experience should be durable if generation later moves from a single synchronous response into staged or job-style processing.

Create

Build the quiz

Topic and study material both lead to a build action. Create should never mean taking the quiz.

Status

Explain the build

Show honest states while the app imports, creates, validates, succeeds, or fails.

Start

Take a ready quiz

Start Quiz remains disabled until a valid quiz exists. It only begins the quiz runner.

Current Chameleon-Button Problem

One primary button changes meaning too much.

The same surface can mean Start, Generate, Regenerate, or New Quiz. In some states, Start creates a quiz and immediately begins it.

  • Users cannot build a clear mental model of what will happen next.
  • Large 30/50-question or source-backed builds look like instant one-shot actions.
  • Failure states are harder to explain because the app is already trying to move into quiz mode.
  • Async or staged generation would require reworking the CTA model later.

Proposed Button Model

Create Quiz Start Quiz
  • Create Quiz: builds from the topic path.
  • Create Quiz from Material: builds from pasted notes, extracted files, or source material.
  • Start Quiz: begins taking the current valid quiz only.
  • Regenerate: should become a secondary create action, not a replacement for Start.

First-Use Roadmap

1 Topic / Material Input

User chooses a short topic or study material without seeing manual syntax.

2 Create Quiz

Create starts the build. Start remains disabled.

3 Build Status

Status shows source ready, creating, validating, ready, or failed.

4 Quiz Ready

A valid parsed quiz exists and is safe to take.

5 Start Quiz

Start unlocks and opens the quiz runner.

6 Results / Explanations

Review score, missed answers, retakes, and explanations.

Build Status States

Idle

Add a topic or study material, then create a quiz.

Source ready

Study material is available and can be used to create a quiz.

Creating

The app is building questions. Larger sources can take longer; public quiz length is capped at 20.

Validating

The response is being checked before Start Quiz can unlock.

Ready

A valid quiz exists. Start Quiz is enabled.

Failed

The new build did not produce a valid quiz. The user can retry with fewer questions or a smaller source.

Topic Path

The simplest first-use path is a short topic plus optional length, difficulty, and question type controls.

  • Primary copy: Use a topic.
  • Main action: Create Quiz.
  • Public length choices: 5, 10, 15, 20.
  • Status after click: Creating quiz from topic...
  • Do not show manual format examples in this path.

Study Material Path

Study material should cover pasted notes and imported files. The user goal is source-grounded practice, not parser management.

  • Primary copy: Use study material.
  • Main action: Create Quiz from Material.
  • Public length choices: 5, 10, 15, 20.
  • Status after import: Study material ready.
  • Status after click: Creating quiz from material...

Advanced / Manual Quiz Import

Formatted-line paste remains useful, but it should not define the beginner experience.

  • Place it under Options, inside Advanced / Manual quiz import.
  • Use copy like: Already have EZ Quiz formatted lines? Paste them here to open or edit a quiz.
  • Rename Parser reference to Manual format reference.
  • Keep Mirror and raw lines out of hero, primary cards, and beginner help.

Failure Rule

Failed creation should not erase the last valid quiz.

  • If a new Create attempt fails, keep the previous ready quiz and keep Start Quiz available for it.
  • If inputs changed, show that Start uses the current ready quiz until Create succeeds.
  • Only replace the ready quiz after validation passes.

Async-Compatible Mental Model

The current backend can stay synchronous for now, but the UX should already look like a build pipeline rather than a magic instant response.

Future Source Ingest

Extract and store source material safely before generation.

Future Coverage Plan

Build a topic/source outline before writing questions.

Future Smaller Batches

Generate groups of questions instead of one large request.

Future Validate / Repair

Dedupe, check answers, and repair weak questions.

Future Final Quiz

Unlock Start only after the final valid quiz is assembled.

Implementation Scope

Can Implement Now

  • Replace chameleon primary action with stable Create and Start Quiz controls.
  • Limit public/default quiz lengths to 5, 10, 15, and 20 questions.
  • Stop auto-start after generation.
  • Add a visible build status region with the six states above.
  • Update landing and help copy around Topic and Study Material.
  • Keep the last valid quiz until a new build validates successfully.
  • Move formatted-line paste language under Advanced / Manual quiz import.
  • Update tests around import-ready copy, Start disabled behavior, and generation failure handling.

Should Wait

  • 30/50-question public generation.
  • Neon-backed generation jobs.
  • Polling, resumable async state, and cross-session job recovery.
  • True staged server progress events.
  • Coverage blueprint generation as a required backend step.
  • Automated dedupe, validation, and repair across batches.
  • Resumable large-file upload architecture.
  • Making structured quiz JSON the default response format.
